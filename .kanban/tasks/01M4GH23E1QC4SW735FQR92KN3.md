title: Do not answer session/prompt with -32800 after the user message is inserted
---
## Problem

The spec says: after the agent inserts the user message, cancellation does not give a `-32800` error on `session/prompt`. The agent answers with the `messageId`.

Now, a `$/cancel_request` for the prompt cancels the handler task (`Connection/Connection.swift:832-838`). If the handler gets to a cancellation point after `insertUserMessage`, `CancellationError` becomes `requestCancelled` (`Connection.swift:932-933`). The deferred echo is still sent after the error (`Connection.swift:884-898`). Also, the deferred work runs on the task that is already cancelled (`Connection.swift:895`). Thus a turn that starts inline in `afterRespondingToCurrentRequest` starts cancelled.

## Work

1. After `insertUserMessage` runs for a request, the connection must send the success response with the `messageId`, also when the task is cancelled.
2. Run the deferred work (`afterRespondingToCurrentRequest`) outside the cancelled task.
3. Add tests:
   - A `$/cancel_request` after insertion gives a success response with the `messageId`, then the echo.
   - A `$/cancel_request` before insertion gives `-32800` and no echo.
   - Deferred work does not see `Task.isCancelled`.

## Acceptance

- The tests above pass, and all other tests pass.
