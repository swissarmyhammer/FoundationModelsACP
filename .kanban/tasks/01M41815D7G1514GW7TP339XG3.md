title: In-band response marker in the session update subscription stream
---
## Problem

FoundationModelsACPClient's `SessionModel` reads `ClientSideConnection.subscribe(to:).updates` in its own task. When `resumeSession(_:)` returns, every earlier `session/update` is already yielded into the stream (the read loop yields a notification before it reads the next frame, `Connection.swift:526`, `:674`, `ClientSideConnection.swift:217`; the response is resolved later in the same loop, `Connection.swift:678`). But the consumer task may not have applied them yet, and `AsyncStream` cannot report "drained". So the client cannot know exactly when the replay is complete, and its `endReplay` can run too early. Agreed with foundationmodelsacpclient-ae on 2026-10-03; its task 6np8vdv waits for this.

## What

Change the element type of `SessionUpdateSubscription.updates` to an enum (choose the final names, document them), for example:

```swift
public enum SessionStreamEvent: Sendable {
    case update(SessionUpdate)
    case responseReceived(id: RequestId, method: String, outcome: Outcome)
    public enum Outcome: Sendable { case succeeded, failed }   // or carry the error
}
```

Rules:
1. For each request that `ClientSideConnection` sends whose params name a `sessionId` (for example `session/resume`, `session/prompt`, `session/close`, `session/set_config_option`), yield ONE `responseReceived` marker into the streams of that session, with the request ID and the wire method.
2. For a response that comes from the wire, yield the marker in the read loop at the point where the response is resolved, so that it comes after every earlier update and before every later one (exact wire order). Yield it BEFORE the caller is resumed.
3. Also yield the marker (with `failed`) when the request fails: error response, cancel, timeout, write failure, or connection close. On close, yield the markers before the stream finishes.
4. A session with no subscriber: the marker goes into the existing per-session buffer like an update, with the same limits and overflow rule (^1heg5df). Decide whether markers count toward the update limit and document it.
5. The deprecated `updates(for:)` wrapper keeps returning `AsyncStream<SessionUpdate>` (it drops the markers), so its users do not break before ^3wfc5m0.

## Acceptance criteria

- Test: updates sent before the resume response all come before the marker, and updates sent after it come after it.
- Tests: a marker with `failed` for an error response, a timeout, a cancel, and a connection close.
- Test: a request without a `sessionId` (for example `initialize`) yields no marker.
- Test: buffered updates and a marker for a session with no subscriber are delivered in order to the first subscriber.
