## Starting point

**This is a rewrite** — see `plan.md` -> *Starting point*. v1 had `newSession`, `listSessions`, `resumeSession`, `closeSession`, `deleteSession`, and `loadSession` on the `Agent` protocol, plus `McpServerWireTests`; all were deleted. Two things changed enough that porting is the wrong instinct:

- **`session/load` -> `session/resume` with `replayFrom`.** Replay is new; there is no v1 equivalent to lean on.
- **MCP server config shape changed** — `"type": "sse"` is removed. The deleted `McpServerWireTests` covered the v1 three-variant union; recreate it for the v2 two-variant one.

Whether `deleteSession` survives into v2 is an open question M0 resolves.

## What

`plan.md` -> **M5**.

- **`session/new`** -- required absolute `cwd`, optional `mcpServers`, optional `additionalDirectories`. Response is `sessionId`. The v1 `modes` field is gone from the response.
- **`session/list`** -- part of the required baseline.
- **`session/resume`** -- replaces v1's `session/load`. Required `sessionId` and absolute `cwd`, optional `mcpServers`, `additionalDirectories`, and **`replayFrom`**. Omit `replayFrom` for a plain reconnect; send `{"type": "start"}` to replay the whole conversation as ordinary session updates. Response is `{}` and **may** include initial session config state.
- **`session/close`** -- the agent **MUST** cancel that session's ongoing work and free its resources. Verify whether `session/delete` also exists (M0 resolves this).
- **`session/set_config_option`** + `config_option_update` replace v1 modes. Categories include `mode`, `model`, `model_config`, `thought_level`.

**MCP server config** (v2 shape): required **`type`** discriminator; `stdio` takes `command` / optional `args` / optional `env`; `http` takes `url` / optional `headers`. **`"type": "sse"` is removed.** Both gated by `session.mcp.stdio` / `session.mcp.http`.

Replay is the mechanism that makes a reconnecting client correct rather than stale, so it is load-bearing for `FoundationModelsACPClient`.

## Acceptance Criteria

- [ ] All four session methods implemented and round-tripping.
- [ ] `cwd` required and absolute; rejected otherwise at decode time.
- [ ] `mcpServers` accepted on both `new` and `resume`, with the `type` discriminator required and `sse` absent.
- [ ] `replayFrom` omitted vs `{"type":"start"}` produce reconnect vs full replay.
- [ ] `session/close` cancels ongoing work.
- [ ] Config options replace modes; `config_option_update` reported.
- [ ] MCP server wire tests exist again, for the v2 variant set.

## Tests

- [ ] Replay from start reproduces the full update sequence in order.
- [ ] Plain resume (no `replayFrom`) replays nothing.
- [ ] A relative `cwd` fails decoding.
- [ ] An `sse` MCP config is rejected or surfaces as unknown, per the schema.
- [ ] `session/close` with work in flight cancels it and frees resources.
- [ ] Config option set + update round-trip for each category.
