    Decisions:
    - The stream pulls. A block is read only when the consumer asks for the next batch, so there is no unbounded buffer. A first design with an AsyncThrowingStream and a producer task was rejected: the producer would read ahead to the end of the file and keep all the batches in memory.
    - The first values (firstPrompt, firstDate) come only from a window that starts at offset 0. An automated Claude Code session thus has no firstDate. The last values come from the tail, else from the head (so a file with one prompt has lastPrompt == firstPrompt).

    - Codex: the tail does not tell if the session is automated (originator is only in session_meta), so the head is always read. Automated = the originator has the word 'exec'. gitBranch = session_meta git.branch. cwd = the last cwd of turn_context or session_meta.

Request from TestudoApp (decision D212, 2026-11-23; design TestudoApp/features/session-import-redesign.md sections 4.2, 4.3, 6, 7).

The import list read each full session file (21 GB on one Mac) and used 15 GB of memory for 20 minutes.

Work in ACPImport:
- A byte source protocol: size, read(offset:length:).
- A metadata reader for Claude Code and Codex that reads only the windows of 4.3: last 64 KB; the last 256 KB one time when the tail gave no cwd; the first 64 KB when the session is not automated. At most 384 KB for each file, never a full file. A window drops a partial first line (tail) or a partial last line (head), also in the middle of a UTF-8 character.
- New metadata fields: isAutomated (Claude Code: entrypoint starts with sdk; no value counts as typed), gitBranch, firstPrompt (cut at 200 characters, not read for an automated session), lastPrompt (cut at 200 characters). No turn count.
- A streaming reader of a full file that gives the updates in batches, keeps at most one block and one line in memory, and stops at a cancellation.
- Keep the old metadata(_ data:) and read(_ data:) API in this step: FoundationModelsACPAgent uses it until D212 step 2. Step 1b removes it.

Tests (section 7, each fails on the code of today): the 50 MB generated file through a counting byte source (at most 384 KB, at most 3 reads typed and 2 automated, the fields equal a full read); a first prompt record larger than 64 KB; a last line that is not complete; a window that starts in the middle of a line or of a UTF-8 character; the streaming reader on a 50 MB file (memory bound, first batch before the end, cancellation); the same for a Codex fixture.
